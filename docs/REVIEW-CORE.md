## Review finding corrected

Financial split commands initially validated financial snapshot size but could commit retained split audit that exceeded the separate planning snapshot's2MiB cap. Accumulating audits while deleting posting parts could then make planning reads/mutations fail integrity checks. Both coordinator and reviewer identified this independently; Builder added a shared conservative raw-planning capacity check to split writes and planning mutations. The ninth acceptance group fills disposable historical split provenance to near that limit, verifies a new split returns400, and checks financial state, planning readability/state and request receipts are unchanged. No partial financial split commits.

Source review confirmed shared owner locks and active/version/scope checks precede receipt replay; planning receipts use a distinct canonical command domain; occurrence identity survives later deletion of the generated transaction; template edits leave saved entries unchanged; split audit is historical rather than another posting. The reviewed additive migration creates planning/provenance tables without financial seed rows or rewriting existing ledger tables.

The coordinator also corrected a legacy hierarchy edge: label-only category budgets must resolve their current category before descendant rollup and same-month parent/child allocation deduplication. Reviewer independently agreed with the identity semantics and added a passing pure group spanning summary, top-level limits and Reports. Explicit category IDs remain stable; null-ID labels resolve only through an exact current catalog name. A legacy Groceries string is not silently remapped when the old category is renamed to Market food. Pending/excluded amounts remain outside spending, limits from different months remain independent, and each covered transaction is counted once. No financial records are rewritten by these presentation/calculation helpers.
